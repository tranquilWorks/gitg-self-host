# M6K 10.06–10.08 learning-loop runtime scope

## Why these three are one bounded cohort

10.06 retrieves and corrects one remembered target, 10.07 turns a complex target
into connected component and whole-task checks, and 10.08 uses a fixed standard to
repair one exposed error. Together they form a retrieval → decomposition → feedback
loop. They are combined only for release mechanics: each competency has separate
materials, prompts, answer keys, source limitations, recovery baseline and runtime
content record. No result in one competency is evidence for another.

The exact GitHub baseline is merge commit
`fe9a47c2e0db2a4c50794e8b7b134ce88b2a63f9` from PR #73. Historical recovery files
remain unchanged; the three baseline YAML files pin the pre-projection runtime
packages for prospective verification.

## Source use

- Karpicke and Roediger (2008) supports the bounded distinction between repeated
  study and delayed retrieval in its reported vocabulary experiments. It does not
  provide a universal schedule or validate this visitor sequence.
- The 4C/ID model supports using whole tasks, supporting information and bounded
  part practice for complex learning. It does not prove that the supplied folder
  hierarchy is optimal or certify skill-design ability.
- Kluger and DeNisi (1996) supports caution that feedback effects vary and can be
  harmful. It does not prescribe this script or authorize coercive criticism.

No source wording, figures, tables, stimuli or proprietary instructional material
are reproduced. All supplied sequences, folders, slips, records, prompts and keys
are original fictional product content.
