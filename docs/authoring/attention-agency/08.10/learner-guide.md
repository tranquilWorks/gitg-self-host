# 08.10 — Completion and perseverance

## Define done before the next burst of effort

Perseverance helps when an important task becomes boring or stalls. Completion also needs a boundary: without one, extra polish can continually move the finish line. A reasoned termination is different from drift, especially when another person relies on a commitment. Ending responsibly may require actual notice, handover or agreement.

Take ten minutes to review at most three open loops, then use up to two ten-minute work windows on one chosen task. Edinburgh's reflection framework [S07](../SOURCES.md#S07) supports moving from observation to an appropriate next action. The closure rules here are original practical choices, not a promise to resolve every obligation through a checklist.

## Three loops and a small finished note

Fictional Jules has three optional personal loops: a room-use note, an unfinished decorative border for that note and a list of possible hobby books. The room note is useful for Jules's own reference and nobody is waiting for it. Choose it as the only active task. Park the book list until Sunday review. The decorative border adds no needed information and can be consciously retired; no dependent person requires notice in this fictional case.

The entire factual material for the room note is: “Use the east entrance. The reading table is beside the window. Return shared pencils to the marked cup.” Done means three short paragraphs, one containing each instruction, saved in a file named “Room note” and reopened to check all three are present. No illustration, elegant wording or public publication is required.

The first work window copies the first two instructions. A plateau arrives when Jules wants a perfect introductory sentence before adding the last instruction. The response is to keep the existing done definition, add the missing pencil sentence and perform the reopen check. The missing item is factual and supplied; more research is unnecessary. Boredom can remain while finishing something still worthwhile.

1. List the three loops and choose an active, parked or ended status for each. State why the active item still matters. Set done before working and identify any people owed delivery or notice in a real task. Do not silently abandon shared duties by changing a private label.
2. Use the first bounded work window, then the second if needed and feasible. At a plateau, identify the exact obstacle and choose a proportionate response: missing information, scope decision, help or simply the next known step. Save the scope and closure plan before the [later record](later-packet.md).
3. Check the artifact against the original done definition. Record actual closure, an honest partial state or a reasoned termination with required communication performed. A drafted notice is not sent notice, and a plan to reopen a file is not a check. Keep the parked review date visible without activating all loops again.

For support, dictate the three supplied sentences or rehearse only the status decisions. For a harder case, someone is relying on a real task: negotiate changes through the agreed channel and preserve unresolved obligations until settled. Finishing after the task loses value is not automatically admirable. Later review can ask whether parked work should restart or end, but today's closure does not prove lifelong perseverance.
