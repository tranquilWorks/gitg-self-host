# 10.08 — Expose one error early and change the work from the feedback

Use a test, model or willing reviewer to reveal a specific weakness, make one targeted correction and verify whether the correction actually helps.

This tests an error-correction loop, not the learner’s character. Feedback is useful only insofar as it is relevant, understandable and connected to a real standard.

Default instruction to improve: put the blue slip in the correct folder and leave the rest there. Supply three folders labeled Today, Later and Reference, a blue slip labeled due today and two unmarked slips. The intended result is the blue slip in Today and the unmarked slips beside the folders. Use synthetic paper only.

Fifteen minutes to prepare a short instruction, ten minutes to test it and fifteen minutes for revision and retest.

## 1. Define the result and invite a test before polishing

Write the intended result separately from the instruction. Give the instruction to a willing adult or follow it literally yourself without filling in hidden assumptions. Observe which object, location or sequence is ambiguous. Ask where did the instruction leave you uncertain, not did you like it. Keep the first version so the feedback can be tied to an actual failure.

- The intended result is explicit before the test
- The first version is preserved
- A literal test or freely consented review occurs
- Feedback identifies an object location or sequence problem

## 2. Turn the feedback into one precise correction

Compare the observed result with the intended one. Select the most consequential error, such as correct folder failing to name Today, and rewrite that sentence to specify the action and destination. Do not change unrelated formatting just to feel productive. If feedback conflicts, ask which interpretation the instructions actually support and choose a testable correction rather than deferring automatically to the most confident reviewer.

- The error is linked to a stated standard
- One correction targets the identified cause
- Unrelated polishing is separated from error correction
- Conflicting feedback is resolved with a checkable interpretation

## 3. Retest with a comparable new example

Use a green slip labeled due today or another equivalent synthetic item. Ask the same literal test of the revised instruction and check whether the intended destination is now unambiguous. Record what improved and what remains unclear, including where the rest should be placed. Decide whether the correction solved the specific failure or simply changed it, and preserve the revision that future users would receive.

- A comparable new example is tested
- The revised instruction is checked against the original goal
- Remaining errors are retained
- The final version reflects observed feedback rather than approval alone

Use pictures, tactile labels, accessible text or a spoken procedure. Self-review is legitimate but should not be described as independent user testing. Keep reviewers free to decline and avoid public criticism or protected workplace material.

Expose one instruction error and verify a targeted repair

Learning guide — unscored

Feedback is useful when it changes a tested gap

Feedback is information about the difference between an intended result and an observed result. It is not automatically correct, kind, relevant or actionable. Fix the standard before testing, preserve the first output, identify one specific object/location/sequence gap, make one targeted change and retest on a comparable fresh case. Praise, confidence and visual polish do not show that the gap closed. Feedback about the task is evaluated against the task; feedback about identity or worth is out of scope. One repaired instruction does not validate a universal feedback method.

Supplied ambiguous instruction and intended result

Folders: TODAY, LATER and REFERENCE, arranged left to right. Objects: one blue slip labeled “due today” and two unmarked white slips, all initially in a row below the folders. Version A instruction: “Put the blue slip in the correct folder and leave the rest there.” Intended result, kept separate from Version A during the literal test: the blue slip is inside TODAY; both white slips remain in their original row below the folders. A test succeeds only if both destination and non-target location are unambiguous from the instruction, not from private knowledge of the intended result.

Example on a different object and location

Intended result: place the red card on shelf 2 and leave the black card on the desk. Version A says “Put the red one away and leave that one.” A literal tester pauses at “away” and cannot resolve what “that one” names. The author records location and reference as the two gaps, selects location first, and revises only to “Place the red card on shelf 2; leave the black card on the desk.” A fresh green card/gray card case reaches the intended locations. “The tester liked it” would not test either gap.

Error-correction record

Intended result fixed before test: __. Version A exact text: __. Test mode [willing reviewer/self literal run]: __. First output or point of uncertainty: __. Gap category [object/location/order/ exception/other]: __. Evidence connecting gap to text: __. Feedback wording: __. Accepted, qualified or rejected and why: __. One selected correction: __. Version B exact text: __. Fresh case and fixed criteria: __. Retest result: __. Remaining gap: __. Keep identities and comments private.

Resolve feedback with the stated standard

Accept feedback when the preserved output exposes a mismatch the instruction permits. Qualify it when the issue is real but outside the fixed target. Reject it when it conflicts with the materials or asks for unrelated preference. Confident wording and majority agreement do not outrank a literal test. For this packet, the smallest complete repair must name TODAY and the original row below the folders. Changing fonts, colors or tone alone cannot repair those semantic gaps.

Make the test accessible, private and voluntary

Use pictures with text, tactile labels, large print, audio, signing, AAC or a helper who moves the slips according to the tester’s directions. Record that support in both runs. A reviewer may decline without consequence; do not use public criticism, humiliation, surveillance or protected work material. Self-review is valid development evidence but is not independent user evidence. For an advanced route, test one more semantic ambiguity—not higher stakes or a less consenting audience.

Retain remaining errors and choose one next loop

If all three fixed criteria pass, retain Version B and test it once in the real low-stakes medium. If the destination passes but white-slip location fails, preserve that partial result and repair only the location clause on a new case. If conditions changed, label the comparison inconclusive. If feedback concerns preference rather than the intended result, track it separately. Stop for coercion, distress, private data or consequences that require a qualified reviewer.
