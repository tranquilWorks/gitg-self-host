# Corrective key — data hygiene

1. A file was retrieved and opened; content verification failed at the third line. Preserve both the original and failed output, identify the correct source/version, and retrieve into a new destination before comparing again. Retyping “gloves” into the result would be an edit, not evidence that the retrieval route worked.
2. Both copies depend on the laptop. The existing test establishes same-device copying only. With an already-authorized separate destination, back up and retrieve the harmless sample into a new folder, then record the access dependencies. Do not lose access deliberately, buy a service to pass, or claim device-loss recovery from a paper plan.
3. The independent Monday version is known to exist. Tuesday's changes are not established as recoverable; the supplied sync service retains no history. A successful Monday restore proves that version's route, not the missing later state. Investigate any other genuine copies without inventing them or overwriting surviving evidence.

Default R1 matches v2. R2 is readable but stale. R3 has no completed retrieval. R4 is incomplete. In the sync scenario, the independent v1 backup is recoverable while v2 is not established. Real testing covers only the actual harmless-file operation and environment used.
